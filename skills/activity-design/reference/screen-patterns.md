# 화면 구성 패턴: 구성요소 조합과 CL 연결

2026-11-09~10, 「Ⅵ-3. 확률의 성질」(20화면)의 저장값을 화면별로 분석한 것이다. 사용자가 직접 고친 화면(10·12·13번)은 **사용자 설계 본보기**로 따로 표시했다. 모든 예는 이 사용자가 만든 활동이다(공식 활동 아님).

## 0. 읽는 법
- 「배치」는 왼쪽 열 → 오른쪽 열 순서다. `[이름]`은 구성요소 별칭(alias)이다.
- 「연결」은 `받는 쪽 sink ← 읽는 값` 이다. 단계 열기는 대부분 `hidden:` sink 하나로 한다.

## 1. 단계 열기(hidden 사슬)의 기본형
| 앞 단계 | 뒤 구성요소의 CL | 쓰는 곳 |
|---|---|---|
| 표 여러 칸이 모두 맞음 | `hidden: not(tbl.script.allOK = 1)` (표 CL에서 `allOK = when ok1 and ok2 1 otherwise 0`) | 1·3·6·8·9번 |
| 표의 특정 칸만 맞음 | `hidden: not(tbl.script.ok1 and tbl.script.ok2)` (표 CL의 변수를 바로 읽음) | 13번(사용자) |
| 표를 다 채움(정답 무관) | `allfill = not(isBlank(this.cellContent(1,1)) or …)` → `hidden: not(tbl.script.allfill)` | 10번(사용자) |
| 객관식 정답 | `hidden: not(mc.matchesKey)` (편집기에서 정답 표시 필요) | 1·9·12번 |
| 객관식 특정 보기 선택 | `hidden: not(mc.isSelected(1))` | 13번 |
| 글 입력 제출 | `hidden: not(txt.submitted)` | 10번(사용자) |
| 글 입력을 정해진 문장과 똑같이 쓰고 제출 | 글 칸 CL `writeOK = this.content = "두 눈이 모두 홀수이다." and this.submitted` → `hidden: not(write.script.writeOK)` | 13번(사용자) |
| 수식 답이 맞음 | 수식 CL `okN = when ok 1 otherwise 0` → `hidden: not(ans.script.okN = 1)` | 8번 |
| 그림판에 충분히 표시함 | `hidden: … or pad.sketch.strokeCount < 9` | 13번(사용자) |
| 그래프 안 상태 | 그래프 식 결과를 `graph.number("c")`로 읽음 | 2·5·6번 |
| 버튼 누름 | `btn.pressCount` | 2·14번 |

- 같은 조건을 쓰는 메모(발문)와 입력칸은 **둘 다 같은 hidden**을 단다(1·3·8·9번). 발문만 보이고 칸이 안 보이는 일이 없게 한다.
- 조건이 길면 받는 쪽이 아니라 **보내는 쪽 CL에서 변수로 만들어** 읽게 한다(`allOK`, `okN`, `writeOK`, `allfill`). 이름 붙은 변수는 `구성요소.script.변수`로 읽는다.

## 2. 피드백 sink
| 구성요소 | sink | 예 |
|---|---|---|
| 표 | `cellSuffix(r,c)` ✅/❌, `correct` | 1·3·6·8·9·12·13번 |
| 수식 답변 | `suffix`, `errorMessage`(틀린 이유 안내), `placeholderLatex`, `correct` | 2·6·8번 |
| 수식 답변(제출형) | `showSubmitButton`, `submitLabel: "확률 확인"`, `resetLabel`, `disableEvaluation: true`, `correct: this.submitted and ok`, `suffix: when not(this.submitted) ""…` | 17~20번 추가과제 |
| 화면 | `subtitle`(단계별 안내·칭찬, `\textcolor{}` 색), `coverText`·`coverButtonLabel`(축하 팝업) | 4·5·6·14번 |
| 객관식 | `prompt`(앞 메모에 발문이 있으면 `""`) | 5·12·13번 |
| 글 입력 | `initialText`(쓸 틀을 미리 줌: 「⑴ 확률이 `0`인 사건:」) | 3번 |
| 그림판 | `hidden`, `disableSketch`, `readOnly` | 14번 |
| 그래프 | `number("변수")`로 다른 구성요소 값을 넣음, `correct`(대시보드), `saveOnChange` | 2·5·8·14번 |

## 3. 구성요소 조합 유형
1. **상황 그림 + 표 → 객관식 → 글 입력** (1번): 왼쪽 그림·상황·표, 오른쪽에 표를 맞히면 객관식 두 개, 둘 다 맞히면 「사건 만들기」 글 입력.
2. **움직이는 그래프 + 객관식으로 조작** (2번): 객관식 선택을 `number("v")`로 그래프에 보내 장면을 재생, 끝까지 보면(`number("w")=3`) 정리 문항이 열림, 다시보기 버튼은 `disabled`로 잠금.
3. **카드 정렬 + 화면 축하** (4번): 카드 정렬은 CL sink가 없어서 화면 CL에서 `sortProb.matchesKey`로 `subtitle`·`coverText`.
4. **체크박스 → 그래프 → 문장 만들기** (5번): 체크박스 `isSelected(1~6)`를 그래프 `number("k_1"…)`로 보내고, 메모 CL에서 고른 맛을 이어 붙여 사건 문장(`show = "사건 A : …"`)을 만든다.
5. **그래프 조작 판정 → 표 → 부등식** (6번): 화면 `subtitle`이 상황별 안내(정답, 너무 넓음, 빠진 점).
6. **표 → 합 → 식, 수직선이 단계마다 바뀜** (8번): 수식 답의 `okN`을 그래프 `number("g_v")`로 보내 그림이 단계적으로 드러남.
7. **방법 비교 표 → 객관식 → 까닭 쓰기** (9번).
8. **필기량으로 힌트 단계** (14번): 그림판 `strokeCount`를 그래프로 보내 `H_hint` 단계를 계산, 화면 `subtitle`이 힌트, 버튼 두 개로 이전 풀이/현재 풀이 전환.
9. **사용자 본보기: 서술 → 제출 → 표 → 답** (10번): 반대 경우를 글로 쓰게 하고(`submitted`), 표는 정답 표시 없이 채우면(`allfill`) 마지막 발문과 답 칸.
10. **사용자 본보기: 고르기 → 같은 문장 쓰기 → 그림판 표시 → 표 → 답** (13번):
   - 왼쪽: `① 상황 + 첫 발문`(메모 하나) → 객관식(정답 표시 없음, 무작위, 목록) → 글 칸(`writeOK`: 고른 문장을 그대로 써서 제출).
   - 오른쪽: `③ 최종 발문`(표를 맞히면) + 답 칸 → `② 안내`(CL `content`에 `oppMCD.choiceContent(1)`를 넣어 「위 '두 눈이 모두 홀수이다.'에 해당하는 경우를 모두 표시한 후 나타나는 표를 채우시오.」) → 표(`writeOK`이고 그림판 9획 이상) → 6×6 그림판(`writeOK`).
   - 단계 번호 ①②③을 발문 앞에 붙여 순서를 보여 준다. 나중에 열리는 ③을 오른쪽 맨 위에 둔다.
11. **사용자 본보기: 그림 선택지** (12번): 체크박스 선택지를 글 대신 그림 4장(격자 배치, 무작위)으로.
12. **M.E.M.O 화면**(7·11번): 공책 줄 배경 그림판 하나. 개념 묶음 끝에 끼운다.
13. **OX 문제 화면**(15번): 메모(문장) + 객관식(O/X) 반복.
14. **돌아보기**(16번): 왼쪽 메모 + 이해도 그래프, 오른쪽 메모 + 글 입력.

## 4. 사용자가 고칠 때 보인 방향 (요약)
- 구성요소 수를 줄이고(상황+첫 발문 합치기, ❌ 메모·확인용 객관식 삭제), 학생 활동(쓰기, 표시하기)을 늘린다.
- 도구는 버튼 대신 단계 조건으로 연다.
- 다음 안내에 학생이 고른 답을 인용한다(`choiceContent`).
- 주석은 그 줄이 하는 일을 한국어로 짧게(`#위의 writeOK라는 변수가 만족되지 않으면 숨김`).
