# 학생이 할 생각별 구성요소 고르기

화면의 구성요소는 「무엇이 만들기 쉬운가」가 아니라 **「이 화면에서 학생이 할 생각을 무엇이 가장 직접 하게 하는가」**로 고른다. 같은 그래프 틀을 모든 개념에 덮으면 화면이 찍어 낸 듯 비슷해지고, 분류·순서·진단처럼 그래프가 필요 없는 생각에서는 그래프가 오히려 방해가 된다.

## 1. 학생의 조작이란
학생의 조작은 점 끌기만이 아니다. 아래가 모두 조작이고, 모두 반응(피드백)을 줄 수 있다.
- 분류하기·짝짓기(카드 정렬), 순서 매기기(정렬 리스트), 고르기(객관식·체크박스), 표시하기·그리기(그림판, Polypad), 채우기(표), 식 쓰기(수식 답변), 이유 쓰기(자유 답변), 누르기(행동 버튼), 끌기(그래프·기하학의 점)
- 반응은 ✅/❌, 화면 부제(`subtitle`), 다음 단계가 열림(`hidden`), 학생이 고른 답을 인용한 안내(`choiceContent`)로 줄 수 있다.

## 2. 대응표
| 학생이 할 생각 | 먼저 검토할 구성요소 | 이런 개념에 | 제작법 | 확인 정도 |
|---|---|---|---|---|
| 분류하기 | 카드 정렬, 체크박스 | 소수/합성수, 유리수/무리수, 함수인 것/아닌 것 | `graph-cl-recipes.md` 6절, 아래 3절, `../knowledge/cl-pitfalls.md` 1절 | 1회 관찰 |
| 짝짓기(표현 바꾸기) | 카드 정렬 | 식 ↔ 그래프 ↔ 표, 지수 꼴 ↔ 로그 꼴 | `graph-cl-recipes.md` 6절 | 1회 관찰 |
| 순서 매기기 | 정렬 리스트 | 수의 크기, 풀이 절차, 증명 단계 | 아래 3절, `../knowledge/cl-pitfalls.md` 1절 | 확인됨 |
| 오개념 진단 | 객관식(오개념을 담은 보기) + 자유 답변(왜) | 부호 규칙, 지수 법칙, 확률의 착각 | 객관식 → 까닭 쓰기 흐름(`screen-patterns.md` 3절 7번) | 확인됨 |
| 연속 변화 관찰 | 그래프(끌 수 있는 점) | 계수에 따른 그래프 모양, 각이 움직여도 같은 값 | `design-rules.md` 2절, `graph-cl-recipes.md` | 확인됨 |
| 도형 구성·측정 | 기하학 | 작도, 길이·각 재기, 무게중심 | `geometry-recipes.md` | 확인됨 |
| 계산 결과 쓰기 | 수식 답변, 표 | 값 구하기, 여러 칸 계산 | `graph-cl-recipes.md` 1·2절 | 확인됨 |
| 모형으로 조작하기 | Polypad | 대수 타일로 넓이 전개, 수 막대 | 아래 3절 | 미확인 |
| 그림 위에 표시하기·풀이 쓰기 | 그림판, Polypad 전체화면 필기 | 경우 세기, 작도 흔적, 풀이 과정 | `editor-ops.md` 8-1, `polypad-fullscreen-writing.md` | 확인됨 |
| 반 전체와 비교 | 표 입력 → 집계 그래프 | 실험 결과, 상대도수, 예측 분포 | `recipe-aggregate.md` | 1회 관찰 (학생 여러 명 동시 입력은 미확인) |
| 조건에 맞는 상황 직접 만들기 | 그래프(조절할 값 여러 개를 끌 수 있는 점으로) + 자유 답변 | 늦게 출발해 먼저 도착하는 경주, 조건을 만족하는 그래프 만들기 | `design-rules.md` 2-1절 예외, `graph-cl-recipes.md` 16절 | 미확인 |
| 예측 → 확인 | 객관식(정답 표시 안 함) → 조작 → 자유 답변 | 결과를 먼저 짐작하게 할 개념 | `design-rules.md` 2절 실험 수업의 흐름 | 확인됨 |

- 한 개념에 생각이 여럿이면 화면을 나누거나, 주 활동 하나를 정하고 나머지는 보조로 둔다.
- 그래프는 다른 생각의 **보조**로 쓸 수 있다. 다만 그래프 라벨·좌표·시작값이 답을 보여 주지 않는지 확인한다(`design-rules.md` 2-2절).

## 3. 제작법이 짧거나 없는 구성요소
- **카드 정렬**: 화면에 다른 구성요소 없이 단독으로 둔다. 함께 두면 카드가 겹친다. 학생 지시는 화면 부제에 쓰고, 설명은 교사 팁에 둔다. 카드 정렬에는 CL sink가 없어서 판정은 화면 스크립트가 `별칭.matchesKey`를 읽어 부제에 띄운다. (1회 관찰)
- **정렬 리스트**: 편집기에서 항목을 정답 순서대로 입력하면 그 순서가 정답이 되고 학생에게는 섞여 나온다. 다른 구성요소의 CL에서 `별칭.matchesKey`를 읽어 판정한다(예: 메모 CL `say = when order.matchesKey "✅" otherwise ""`, 내용에 `${say}`, 또는 다음 단계 `hidden: not(order.matchesKey)`). 정렬 리스트 자체에는 ✅/❌를 붙이는 sink가 없으므로 피드백은 메모·부제·다음 단계 열림으로 준다. (확인됨)
- **조작 시험은 사람이 직접 하거나 상태 값으로 확인한다.** 스크립트로 끌기를 흉내 내면 화면 모양만 바뀌고 순서·위치 값은 바뀌지 않을 수 있다. 그 결과만으로 「동작하지 않는다」고 판정하지 않는다. (확인됨)
- **Polypad 부분 화면(대수 타일 등)**: 화면 일부에 Polypad를 넣어 모형을 조작하게 하는 제작법은 아직 없다. 계획에 넣으면 화면 복사본에서 먼저 시험한다. (미확인)
- 제작법이 없어서 다른 구성요소로 바꿔야 하면 말없이 바꾸지 않는다. 「계획 대비 후퇴」로 구성표와 종료 보고(G4)에 적고 교사에게 묻는다.
