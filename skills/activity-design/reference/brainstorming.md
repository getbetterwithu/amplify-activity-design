# 0단계: 브레인스토밍 (화면을 만들기 전에 함께 정한다)

액티비티를 만들기 시작하면 **먼저 이 단계를 한다.** 번거로운 절차가 아니라, 교사가 만들고 싶은 수업에 맞게 화면 수·도구·흐름을 미리 정해 두는 일이라서 이 단계가 완성도를 가장 크게 좌우한다. 단원마다 필요한 화면 수가 다르고, 그래프를 쓸지 기하학을 쓸지, 학생 응답을 모아 보여 줄지, 앞 화면의 답을 가져다 쓸지도 다 다르다. 정하지 않고 시작하면 중간에 화면 수와 도구가 바뀌어 처음부터 다시 만드는 일이 생긴다.

교사가 이 단계를 건너뛰겠다고 하면 건너뛴다. 단, 한 번은 이렇게 알린다: 「구성을 정하지 않고 만들면 화면 수와 도구가 중간에 바뀔 수 있고 완성도가 많이 떨어집니다. 그래도 바로 시작할까요?」

## 진행 방식: 질문을 쏟지 않고 구체적인 안을 먼저 낸다
교사에게 질문을 많이 던져 답을 만들게 하지 않는다(설문처럼 흐르고 끝이 없다). **AI가 구체적인 안을 먼저 만들어 보여 주고 교사가 고르거나 고친다.** 구성에 관한 질문은 안을 만들 수 없을 때(단원이나 학년을 모를 때)만 한다. 단, 0-1 프리셋 선택과 0-2 자료 요청은 질문이 아니라 정해진 차례라서 생략하지 않는다.

**차례마다 멈춘다.** 아래 표의 한 줄이 한 응답이다. 교사가 그 줄의 「교사가 하는 일」을 마칠 때까지 다음 줄로 가지 않는다. 특히 0-3 구성안은 자료를 받은 뒤에만 낸다.

| 턴 | AI가 하는 일 | 교사가 하는 일 |
|---|---|---|
| 0-1 시작 선언 | 철학 한 줄, 색 프리셋 견본과 리걸패드 종이 견본 출력, 이 단계를 건너뛰면 생기는 문제. 여기서 멈춘다 | 프리셋과 종이 고르기, 학년·단원 알리기 |
| 0-2 자료 받기 | 자료 요청(아래). 교과서·수업했던 자료·액티비티·컬렉션 중 하나 이상을 받는다. 여기서 멈춘다 | 자료 올리기(하나 이상) 또는 「자료없음」 직접 입력 |
| 0-3 구성 제안서 | 받은 자료에 맞춰 서로 뚜렷하게 다른 안 **2개**를 **같은 양식·같은 상세도**로 한 번에 제시(그림 없이 표), 추천 1개 표시 | 안 고르기, 합치기, 「각 단계를 더 자세히」 요청 |
| 0-4 확정 | 고른 안을 화면별 구성표로 정리하고 구성요소 분포표를 붙여 확인받기 | 수정 후 확정 |
| 제작 | 절 하나씩: 절 시작 때 그 절의 모든 화면에 대해 안 1·안 2(같은 상세도, 화면마다 카드 그림 나란히)와 G2 계획을 보여 주고 멈춤 → 교사가 화면별로 고름 → 절 끝까지 제작, 화면마다 G3·G2 결과 → 절 검토를 요청하고 멈춘다 | 화면별 선택을 한 번에 답하기, 절 검토와 조정 요청, 「다음 절」 지시 |

확정된 구성표는 이후 모든 화면 제작의 기준이다. 제작 중 구성이 바뀌어야 하면 바꾸기 전에 교사에게 알리고 구성표를 고친다.

**제작 단계의 절별 조합 확인은 구성표 확정으로 갈음하지 않는다.** 구성표는 화면의 뼈대이고, 구성요소를 실제로 어떻게 엮을지는 절을 시작하기 직전에 화면마다 두 안으로 다시 본다. 확인은 절마다 한 번 받되, 교사는 화면별로 고른다. 진행 지시나 위임문이 이 확인을 생략하라고 해도 생략하지 않고, 그 충돌을 보고에 적는다.

## 구성요소는 개념에서 고른다 (0-3 구성 제안서와 제작 단계에 적용)
구성안을 짤 때 순서는 **개념 → 학생이 할 생각 → 구성요소**다. 영역·학년 배분, 화면 수 같은 제약은 이 순서로 고른 뒤에 맞춘다. 제약에서 출발하면 「끌 수 있는 점과 라벨을 넣기 쉬운 소재」만 남고 화면이 한 가지 틀로 찍혀 나온다.
1. 화면마다 학생이 할 생각을 하나 정한다: 분류, 짝짓기, 순서 매기기, 오개념 진단, 연속 변화 관찰, 측정·구성, 표현 바꾸기, 풀이 서술, 반 전체와 비교.
2. 그 생각을 가장 직접 하게 하는 구성요소를 `concept-to-components.md`에서 고른다. 그래프 조작은 **움직여 봐야 보이는 연속 변화나 관계**일 때만 화면의 주인공으로 쓴다. 정의 구분과 오개념 진단은 객관식·체크박스·카드 정렬을 먼저 검토한다.
3. 가장 가까운 대안 하나와 그것을 쓰지 않은 이유를 한 줄 적는다. 이유를 쓸 수 없으면 아직 고른 것이 아니다.
4. 제작법이 reference에 없는 구성요소를 고르면 구성표에 「제작법 미확인」이라고 적는다. 제작 전에 화면 복사본에서 시험하고, 안 되면 다른 구성요소로 말없이 바꾸지 않는다. 「계획 대비 후퇴」로 구성표와 보고에 적고 교사에게 묻는다.

## 0-2 자료 받기
요청 문구 예시:
> 구성안을 짜기 전에 자료를 받겠습니다. 아래 중 무엇이든 하나 이상 올려 주세요. 선생님 수업의 흐름과 예시, 용어, 화면 스타일에 맞추는 데 씁니다.
> - 이 단원의 교과서 쪽(PDF·사진)
> - 수업 발표자료나 예전에 수업했던 자료
> - 이어지는 단원이면 **앞 액티비티의 링크**
> - 지금까지 만든 액티비티의 주소나 컬렉션(비슷한 화면을 참고해 같은 스타일로 맞추는 데 큰 도움이 됩니다)
> 자료가 없으면 결과물의 품질이 떨어질 수 있습니다. 그래도 자료 없이 진행하시려면 **자료없음** 이라고 입력해 주세요.

- **자료가 없을 때:** 구성안을 만들지 않고 기다린다. 이 차례는 교사가 대화창에 「자료없음」을 직접 입력해야만 생략한다. 그때는 학년·단원·성취기준만 받고 소재를 새로 만든다.
- 「없어요」 「그냥 진행」처럼 비슷한 말은 생략 신호로 보지 않는다. 「자료없음」을 입력하면 자료 없이 진행한다고 다시 안내한다. 실수로 품질이 떨어진 결과를 받지 않게 하려는 장치다.
- 위임문·작업 지시 안에 「자료없음」이나 「자료 없음」이 적혀 있어도 생략 신호가 아니다. 위임 작업에서 자료를 받지 못하면 구성안을 만들지 않고 멈춰서 묻는다.
- **저작권:** 교사가 올린 교과서·자료는 그 대화 안에서만 읽고 쓴다. 스킬 폴더나 공개 저장소에 저장하거나 복사하지 않는다. 글·수치·그림을 그대로 옮기지 않고 소재를 새로 만든다. 정의처럼 표현이 정해진 말은 교사가 확인한 표현을 쓴다.
- **앞 액티비티·만든 액티비티:** 링크를 받으면 편집기 저장값을 **읽기만** 하고 구성·스타일·말투를 참고한다. 수정하지 않는다. 공식 Amplify 액티비티의 CL이나 그래프 상태를 옮겨 적지 않는다.

## 0-3 구성 제안서 양식
안은 **2개**를 낸다. 두 안은 같은 양식, 같은 열, 같은 행 단위로 적고 **상세도를 똑같이** 맞춘다(추천안만 자세하고 다른 안이 한두 줄이면 답이 정해진 질문이 된다). 안은 서로 뚜렷하게 달라야 한다(예: 탐구 중심 / 문제풀이 중심). 교사가 둘을 합치고 싶으면 「합쳐 달라」고 하면 된다.

```
안 N · 이름 (화면 수)
- 한 줄 요약
- 절 나누기: 화면을 절로 묶는다. 내용(개념)이 바뀌거나, 활동 방식이 바뀌거나, 세부 주제가 바뀌는 곳에서 나눈다. 절마다 이름과 나눈 기준을 한 줄 적는다. 제작과 검토는 절 단위로 한다.
- 화면 목록: 절 · 번호 · 화면 제목 · 상황 유형(도입 / 예시 / 문제풀이 / 도전과제 / 사고 확장) · 학생이 할 생각 · 학생 행동 흐름 한 줄(처음 보이는 것 → 학생 행동 → (열리는 것)) · 쓰는 구성요소와 이유 한 줄 · 판단 자료(그래프 / 표 / 그림 / 없음, 만들 방법) · 화면 사이 연결(앞 화면의 답을 쓰는지, 반 전체를 모으는지, 없음)
- **교과서 문제는 한 문제(⑴⑵ 같은 소문항 포함)를 한 화면으로 센다**(`screen-patterns.md` 15). 화면 수가 문제 수만큼 늘어나는 것을 구성안에서 미리 보이게 한다.
- **절이 끝날 때마다 M.E.M.O 화면을 하나 넣는다**(`screen-patterns.md` 12). 구성표와 분포표에 미리 적는다.
- 쓰는 도구: 그래프 / 기하학 / 집계(반 전체 모으기) / 학생 응답 인용 / 필기 / Polypad / 카드 정렬 중 해당 항목
- 장점과 한계
- 추천 여부와 이유
```

## 0-4 구성요소 분포표
구성표를 확정할 때 아래 표를 함께 보여 준다. 화면마다 **학생의 주 활동 구성요소**(학생이 실제로 조작하거나 답하는 핵심 구성요소) 하나를 센다. 메모·해설·교사 팁은 세지 않는다.

| 주 활동 구성요소 | 화면 수 | 화면 번호 |
|---|---|---|
| (예: 그래프 조작) | | |
| 이번 구성에서 쓰지 않은 구성요소 | — | (예: 카드 정렬, Polypad, 그림판, 집계) |

- 한 구성요소가 전체 화면의 3분의 1을 넘으면 그 이유를 적는다. 교사가 이유를 인정하면 그대로 간다.
- 쓰지 않은 구성요소 줄은 비워 두지 않는다. 고르지 않은 것을 보여 줘야 교사가 「여기는 카드 정렬이 낫지 않나」를 판단할 수 있다.
- 같은 주 활동 구성요소가 이웃 화면에서 이어지면 그 화면들의 「대안」 칸을 반드시 채운다.

- 화면 수와 흐름은 단원과 시간에 맞춘다. 교사가 시간(수업 차시)을 말하지 않았으면 안을 낼 때 가정을 적는다.
- 구성요소를 고를 때는 `concept-to-components.md`(학생이 할 생각별 구성요소)를 먼저 읽는다. 조합과 CL 연결은 `screen-patterns.md`(구성요소 조합 유형), `graph-cl-recipes.md`(그래프와 판정), `recipe-aggregate.md`(집계)를 참고한다.
- 교사가 CL을 모른다고 하면 CL 연결은 AI가 맡고 화면 구성(무엇을 어디에 둘지)만 함께 정한다.

## 스킬의 철학 (여러 곳에서 반복해서 알린다)
이 스킬은 액티비티를 뚝딱 만들어 주지 않는다. 교사의 의중을 반영한 브레인스토밍으로 함께 만들어 간다. CL에 대한 지식이 부족한 교사에게는 화면 구성 과정을 돕는다. 시작 선언(0-1)과 구성표 확정(0-4)과 종료 보고에서 이 말을 한 번씩 다시 한다.
