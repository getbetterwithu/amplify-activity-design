# 0단계: 브레인스토밍 (화면을 만들기 전에 함께 정한다)

액티비티를 만들기 시작하면 **먼저 이 단계를 한다.** 번거로운 절차가 아니라, 교사가 만들고 싶은 수업에 맞게 화면 수·도구·흐름을 미리 정해 두는 일이라서 이 단계가 완성도를 가장 크게 좌우한다. 단원마다 필요한 화면 수가 다르고, 그래프를 쓸지 기하학을 쓸지, 학생 응답을 모아 보여 줄지, 앞 화면의 답을 가져다 쓸지도 다 다르다. 정하지 않고 시작하면 중간에 화면 수와 도구가 바뀌어 처음부터 다시 만드는 일이 생긴다.

교사가 이 단계를 건너뛰겠다고 하면 건너뛴다. 단, 한 번은 이렇게 알린다: 「구성을 정하지 않고 만들면 화면 수와 도구가 중간에 바뀔 수 있고 완성도가 많이 떨어집니다. 그래도 바로 시작할까요?」

## 진행 방식: 질문을 쏟지 않고 구체적인 안을 먼저 낸다
교사에게 질문을 많이 던져 답을 만들게 하지 않는다(설문처럼 흐르고 끝이 없다). **AI가 구체적인 안을 먼저 만들어 보여 주고 교사가 고르거나 고친다.** 질문은 안을 만들 수 없을 때(단원이나 학년을 모를 때)만 한다.

| 턴 | AI가 하는 일 | 교사가 하는 일 |
|---|---|---|
| 0-1 시작 선언 | 철학 한 줄, 색 프리셋 견본 출력, 필요한 자료 안내, 이 단계를 건너뛰면 생기는 문제 | 프리셋 고르기, 학년·단원 알리기 |
| 0-2 자료 받기 | 자료 요청(아래), 이어지는 단원이면 앞 액티비티 링크 요청 | 자료 올리기 또는 「없음」 |
| 0-3 구성 제안서 | 안 2~3개를 한 번에 제시, 추천 1개 표시 | 안 고르기, 합치기, 「각 단계를 더 자세히」 요청 |
| 0-4 확정 | 고른 안을 화면별 구성표로 정리해 확인받기 | 수정 후 확정 |
| 제작 | 화면 하나씩 구성요소 조합 1~2안 → 확인 → 제작 → 점검(`lint.md`) | 화면별 확인 |

확정된 구성표는 이후 모든 화면 제작의 기준이다. 제작 중 구성이 바뀌어야 하면 바꾸기 전에 교사에게 알리고 구성표를 고친다.

## 0-2 자료 받기
요청 문구 예시:
> 단원 내용을 구체적으로 만들려면 자료가 있으면 큰 도움이 됩니다. 아래 중 있는 것을 올려 주세요.
> - 이 단원의 교과서 쪽(PDF·사진) 또는 수업 발표자료·예전에 쓰던 수업자료
> - 이어지는 단원이면 **앞 액티비티의 링크**
> - 지금까지 만든 액티비티의 주소나 컬렉션 (비슷한 화면을 참고해 같은 스타일로 맞추는 데 큰 도움이 됩니다)
> 없으면 학년과 단원, 성취기준만 알려 주셔도 됩니다. 이 경우 소재는 제가 새로 만들고, 구체성은 떨어질 수 있습니다.

- **자료가 없을 때:** 학년·단원·성취기준만 받고 소재는 새로 만든다. 구체성이 떨어질 수 있다고 알린다. 자료 없이 바로 시작하겠다고 하면 시작한다.
- **저작권:** 교사가 올린 교과서·자료는 그 대화 안에서만 읽고 쓴다. 스킬 폴더나 공개 저장소에 저장하거나 복사하지 않는다. 글·수치·그림을 그대로 옮기지 않고 소재를 새로 만든다. 정의처럼 표현이 정해진 말은 교사가 확인한 표현을 쓴다.
- **앞 액티비티·만든 액티비티:** 링크를 받으면 편집기 저장값을 **읽기만** 하고 구성·스타일·말투를 참고한다. 수정하지 않는다. 공식 Amplify 액티비티의 CL이나 그래프 상태를 옮겨 적지 않는다.

## 0-3 구성 제안서 양식
안마다 같은 양식으로 적는다. 안은 서로 뚜렷하게 달라야 한다(예: 탐구 중심 / 문제풀이 중심 / 혼합).

```
안 N · 이름 (화면 수)
- 한 줄 요약
- 화면 목록: 번호 · 화면 제목 · 상황 유형(도입 / 예시 / 문제풀이 / 도전과제 / 사고 확장) · 쓰는 구성요소
- 쓰는 도구: 그래프 / 기하학 / 집계(반 전체 모으기) / 학생 응답 인용 / 필기 / Polypad 중 해당 항목
- 장점과 한계
- 추천 여부와 이유
```

- 화면 수와 흐름은 단원과 시간에 맞춘다. 교사가 시간(수업 차시)을 말하지 않았으면 안을 낼 때 가정을 적는다.
- 조합 아이디어가 필요하면 `screen-patterns.md`(구성요소 조합 유형), `graph-cl-recipes.md`(그래프와 판정), `recipe-aggregate.md`(집계)를 참고한다.
- 교사가 CL을 모른다고 하면 CL 연결은 AI가 맡고 화면 구성(무엇을 어디에 둘지)만 함께 정한다.

## 스킬의 철학 (여러 곳에서 반복해서 알린다)
이 스킬은 액티비티를 뚝딱 만들어 주지 않는다. 교사의 의중을 반영한 브레인스토밍으로 함께 만들어 간다. CL에 대한 지식이 부족한 교사에게는 화면 구성 과정을 돕는다. 시작 선언(0-1)과 구성표 확정(0-4)과 종료 보고에서 이 말을 한 번씩 다시 한다.
