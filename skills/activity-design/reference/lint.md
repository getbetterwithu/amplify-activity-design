# 저장 직후 점검 (관문 G3)

화면을 저장할 때마다 이 점검을 돌린다. 말로 확인했다고 하지 않고 **실행해서 결과 전체를 읽는다**(빈 항목도 포함). 결과와 아래 표는 교사 화면에 붙이지 않는다(`SKILL.md` 「교사에게 보이는 말」). 교사나 지침이 점검 내역을 보여 달라고 할 때만 전체를 보여 준다. 점검은 저장값을 읽기만 하며 활동을 바꾸지 않는다.

- **「필수 실패」가 1건이라도 있으면 그 화면은 「완료」라고 쓰지 않는다.** 고친 뒤 다시 돌려 0건을 확인한다. 끝내지 못한 화면은 교사에게 「완료」가 아니라 「미완성: 빠진 것」으로 말한다.
- 「검토 필요」는 항목마다 **정상이라고 볼 근거를 확인하거나** 고친다. 근거 없이 넘기지 않는다.
- 나머지(수식·표기·배치 등)는 2절 표대로 고친다. **한 항목의 0건(예: 「수식 0건」)을 점검 통과처럼 쓰지 않는다.**
- **완료는 두 단계로 나눠 쓴다.** ① 「저장 점검 통과」: 필수 실패 0건이고 2-3절 계획 대조에서 빠진 것 0건. ② 「작동 확인 완료」: 학생 미리보기에서 입력·끌기·제출·단계 열림을 직접 해 보고 결과를 적음(G2 4번). 해 보지 못한 것은 「작동 미확인」이라고 쓰고 통과로 바꾸지 않는다. 화면이 완성됐다고 말할 수 있는 것은 두 단계를 모두 마친 화면뿐이다.

## 1. 점검 스크립트
편집기 탭에서 `scripts/lint-saved.js`의 내용을 그대로 실행한다(저장값 읽기). 코드는 세션에서 한 번 읽어 두고 저장할 때마다 다시 실행한다. 내부 API 이름은 Amplify가 바꿀 수 있으니 오류가 나면 `editor-ops.md` 1절의 읽기 방법으로 화면 배열을 얻어 같은 규칙으로 직접 검사한다. (확인됨)

## 2. 결과를 읽는 법
| 항목 | 뜻 | 걸리면 |
|---|---|---|
| **필수 실패** | 학생이 풀 수 없는 화면: 발문인데 답 수단이 없음, 표 머리글이 모두 비어 있음, 빈 표, 「그래프를 이용하여」인데 그래프가 비어 있거나 판단 자료가 없음, 그리라는 발문인데 그릴 수단(그림판·끌 수 있는 그래프)이 없음 | **고치고 다시 돌려 0건이 되기 전에는 「완료」라고 쓰지 않는다.** 이유를 적어 넘기는 항목이 아니다. 정말 정상인 구성이면 점검이 틀린 것이므로 교사에게 알리고 `scripts/lint-saved.js`를 고친다. (확인됨) |
| **검토 필요** | 정상일 수도 있는 것: 끌기·그리기 그래프만 있는 발문, 그림판만 있는 자료 화면, 그림판 없이 그래프만 있는 그리기 발문, 풀이 공간 없음, 일부 표 머리글 비어 있음, 빈 그래프, 카드 정렬과 다른 구성요소를 함께 둠(전체 화면 구성요소라 편집기에서는 이렇게 만들 수 없으니 붙여넣기로 생긴 구성인지 본다) | 항목마다 **정상이라고 볼 근거를 확인하거나** 고친다. 근거 없이 넘기지 않는다. (확인됨) |
| 수식 | 수식 노드 밖 일반 글에 `^`, `\`, `변수 = 값`, 분수 꼴, `sin`, 문자 변수(「x축」의 x), `x²`가 남음. 객관식 선택지·카드·표 칸의 일반 글도 포함(화면 제목은 제외) | 해당 글을 수식 노드로 바꾼다(`editor-ops.md` 5절, 9-2절). 단어 속 `=`처럼 정말 일반 글이면 그대로 둔다. |
| 표기 | 수식 안에서 `\mathrm{}`·`\mathbf{}` 밖에 대문자가 있음(점 이름이 기울어질 수 있음) | 점 이름이면 `\mathrm{}`으로 감싼다(같은 화면의 점 이름을 모두 맞춘다). 상수·집합 기호처럼 정말 점 이름이 아니면 그대로 둔다. 안내이며 실패 처리하지 않는다. |
| 경고 | 편집기가 오류·경고로 표시하는 것을 저장값에서 미리 잡음(수식 답변 CL의 `prompt`, 각도법 그래프) | 수식 답변 CL에서 `prompt` 줄을 지우고 질문을 앞 메모에 둔다. 그래프 설정에서 각도 단위를 호도법으로 맞춘다. |
| 배치 | 한 문단에 `·`로 항목 5개 이상을 이어 붙임, 한 문단이 100자 이상, 또는 부제 한 줄이 55자 초과(부제는 자동 줄바꿈 없음) | 한 줄에 하나씩 나누거나 2열로 나눈다(`design-rules.md` 3-1절). 안내이며 실패 처리하지 않는다. |
| 이미지 | 이미지 대체 텍스트가 비어 있음, 또는 테두리 표시가 꺼져 있음(안내) | 이미지 내용 전문을 쓴다(`design-rules.md` 7절). |
| 서식 | 큰 글자가 2단계가 아님 | 안내만 한다. 쓸지 말지는 사용자 지침(`design-rules.md` 3절). |
| 참조 | CL이 읽는 구성요소 이름이 활동에 없음 | 이름을 맞추거나 CL을 고친다(`design-rules.md` 2-3절). |
| 완성도 | 지시 문장에 h2 없음, 그래프 판정에 학생 반응 없음, 피드백 표기 섞임, 색 글자 0개 | 화면 완성 기준표(3절)로 확인한다. 교사가 검토하는 화면처럼 정상인 경우는 그대로 둔다. 안내이며 실패 처리하지 않는다. (확인됨) |
| 정답표시 | 객관식·체크박스마다 정답으로 표시된 선택지 | 설계와 맞는지 사람이 본다. 예상·의견 문항인데 정답이 표시돼 있거나, 정답 문항인데 「정답 표시 없음」이면 고친다. 안내이며 실패 처리하지 않는다. |

- **자동 점검 0건은 「표기·참조 오류 없음」이라는 뜻이지 화면이 완성되었다는 뜻이 아니다.** 자동 점검 결과와 화면 완성 기준표(3절) 결과를 따로 본다.
- **점검이 못 하는 것:** 한 문장 안에 여러 요구(「축의 방정식과 꼭짓점의 좌표를 각각 구하시오」)가 있어도 코드는 문장 수만 센다. 요구마다 칸이 있는지는 G2 3번이 맡는다. 「교과서 문제 화면」인지는 코드가 모르므로 풀이 공간은 「검토 필요」로만 알리고, 계획에 풀이 공간이 있었는지는 2-3절이 본다.
- **보고 규칙:** 결과 전체는 교사 화면에 붙이지 않고 평문으로 요약한다(고친 것 한 줄, 교사가 정해야 할 것, 해 보지 못한 것). 점검 내역을 보여 달라는 요청이 있으면 첫 줄에 「필수 실패 N건 · 검토 필요 M건」을 쓰고 결과 전체를 그대로(빈 항목 포함) 붙인다. 필수 실패가 있는 화면은 「완료」로 말하지 않는다.
- 교사 참고 사항 안의 긴 문단 안내는 고치지 않아도 된다(학생이 보지 않는다).
- 점검에 걸린 것이 0건이어도 **편집기에 표시되는 경고(문법 오류, 다른 화면 참조, 없는 대상 참조, 각도법)는 별도**다. 이 경고는 저장값에 없으므로 아래 2-2절의 코드로 편집기 화면에서 읽는다. 통과 조건은 「경고 아이콘이 없다」이다.
- 학생 미리보기에서 수식이 실제로 그려지는지는 이 점검으로 알 수 없다. 수식이 있는 화면은 미리보기로 한 번 확인한다.

## 2-0. 시작 상태 정답 노출 확인 (사람이 본다)
점검 스크립트는 정답을 모르므로 이 항목을 잡지 못한다. 저장 직후 학생 미리보기를 처음 연 상태(아무것도 조작하지 않은 상태)에서 아래 표를 안에서 채운다(교사 화면에 쓰지 않는다).

| 화면 | 보이는 값(그래프 라벨, 점 좌표, 표 칸, 부제, 메모) | 이 화면의 정답 | 정답이 보이거나 바로 읽히는가 |
|---|---|---|---|

- 「예」가 하나라도 있으면 완료가 아니다. 라벨을 숨기거나(조건부 식, `graph-cl-recipes.md` 7절), 시작값을 정답과 다른 값으로 바꾸거나, 질문을 바꾼다.
- 학생이 점을 끌어 값을 찾아내는 화면이면 끌기 전에는 정답이 보이지 않아야 한다. 끌어서 찾는 것 자체가 활동이면 그 사실을 표에 적는다.

## 2-1. 미리보기 스크롤 확인
학생 미리보기를 연 상태에서 실행한다(화면마다). 세로로 스크롤되는 영역이 있으면 목록으로 나온다. 목록이 비어 있으면 가장 좋고, 남으면 양과 원인을 보고에 적는다(실패 처리하지 않는다). 찾은 화면은 글 줄이기만 바로 하고, 그 밖의 구성 변경(열 나누기, 화면 나누기, 구성요소 바꾸기·삭제·이동)은 넘친 양·원인 구성요소·고칠 안을 보여 주고 교사에게 묻는다(`SKILL.md` 일하는 순서 2). (확인됨)

`scripts/check-scroll.js`를 실행한다.

- 미리보기 크기는 브라우저 창에 따라 달라진다(고정된 16:9가 아니다). 결과와 함께 **측정한 창 크기**를 적는다. 예: 「1440×900 창, 넘침 없음」.
- 조작이 가려지면 먼저 카드·화면 위치를 옮기거나 대상을 화면 안으로 굴린다. 화면 배율 조정은 마지막 수단이다(배율은 사이트별로 기억되어 사용자 탭에 남는다). 배율을 바꿨으면 판정 전에 되돌리고, 되돌렸는지 확인한다.

## 2-2. 편집기 경고·오류 아이콘 읽기
화면 목록이 다 그려진 편집기에서 실행한다. 경고가 있는 화면 번호와 종류가 나온다. 목록이 비어 있어야 통과다. (확인됨)

`scripts/check-warnings.js`를 실행한다.

- 종류 `warning-color`는 노란 경고, `error-color`는 빨간 오류다.
- 문구는 아이콘에 마우스를 올리면 나오는 풍선(`.dcg-tooltip-message`)에 있다. 누르지 않아도 된다.
- 오류가 있는 구성요소는 그 화면을 연 뒤 「스크립트 열기」 버튼의 `오류 있음` 표시로 찾고, 코드 칸의 빨간 밑줄에 마우스를 올리면 편집기가 「없는 sink이고 유효한 sink는 …」 같은 정확한 문구를 알려 준다. 값을 고치지 않고 읽기만 한다. 스크립트 창에는 닫기 버튼이 없을 수 있으니 열었다면 값을 넣지 않은 채 편집기를 다시 불러 닫는다. (확인됨)

## 2-3. 계획 대 저장값 대조 (구성요소가 빠졌는지)
자동 점검은 「계획에 있던 구성요소가 통째로 빠졌는지」를 모른다. 절을 만든 뒤 **절 시작 때 확정한 구성요소를 적고** 저장값과 대조한다. 편집기 탭에서 실행한다(저장값 읽기). (확인됨)

`scripts/check-plan.js`를 열어 파일 앞부분의 `PLAN`·`SCREEN_COUNT`·`FREE`·`LINES`·`CARDS`·`ROWS`를 채운 뒤 편집기 탭에서 실행한다. 채우는 법은 파일 안 주석에 있다.

- **카드를 고른 화면은 `PLAN`을 손으로 쓰지 않고 `CARDS`(카탈로그 계약 표)와 `ROWS`(구성표 줄)를 옮겨 적는다.** 코드가 둘에서 PLAN을 만든다. 슬롯 선택이 구성표에 없거나 계약에 없는 값이면 추측하지 않고 「빠진 것」으로 센다. 카드 계약에 `단독`이 있으면 그 구성요소만 있어야 한다. 번호 없이 승인받은 G2 계획 표는 `PLAN`에 그대로 적는다.
- **「계약 없는 화면」** 은 이번 PLAN에 없는 화면이다(앞 절의 화면도 나온다). 이번 절의 화면이 여기 있으면 구성표에 확정 조합이 없는 것이니 만들기 전에 교사에게 묻는다. 일부러 자유 구성으로 둔 화면이면 구성표에 그 사실이 적혀 있어야 한다.
- **`PLAN`이 비었거나 구성표 화면 수와 다르면 「빠진 것」으로 센다.** 검사를 줄여서 통과하는 길을 막기 위해서다. `FREE`는 교사가 「카드 없음」을 요청해 구성표에 적은 경우에만 `true`로 바꾼다.
- **빠진 것이나 화면 없음이 1건이라도 있으면 그 화면은 「완료」가 아니다.** 「미완성: 빠진 것」 목록에 쓰고, 만들지 못한 이유(제작법 없음, 저장 안 됨 등)를 적고, 다른 구성요소로 바꾸려면 교사에게 먼저 묻는다(「계획 대비 후퇴」).
- 「계획에 없음」은 교사에게 물어 바꾼 것인지 G2 1번 결과 칸에 적는다. 묻지 않고 바꾼 것이면 되돌린다.
- 구성요소가 저장되지 않았는지는 만든 직후 이 점검으로 본다. 버튼을 눌렀다는 사실이 아니라 저장값에 키가 있는지가 증거다.

## 3. 화면 완성 기준표 (관문 G2)
규칙은 여러 문서에 흩어져 있어 화면을 만드는 순간 떠올리기 어렵다. 그래서 화면마다 **이 문서를 다시 열어** 아래 표를 채운다. 기억으로 채우지 않는다.
- **만들기 직전**: 1~4번의 「계획」 칸을 채운다. 비어 있으면 만들지 않는다.
- **저장 직후**: 1~9번의 「결과」 칸을 채운다. 「아니오」가 있으면 고친 뒤 다시 채운다.
- 계획과 결과는 안에서 채우고 교사 화면에 쓰지 않는다(별도 기록 파일은 만들지 않는다). 다만 **교사가 확정한 조합(화면별 안 번호, 삽화 여부, 풀이 공간 종류)은 계획 칸의 원본인 구성표의 그 절 줄에도 한 줄 적는다**(`SKILL.md` 「일하는 순서」 2). 대화가 요약돼도 구성표에 남는다.
- **계획 칸을 채울 때 쓸 구성요소를 키 이름으로 적는다**(2-3절 PLAN에 그대로 넣는다).

| 항목 | 만들기 직전 (계획) | 저장 직후 (결과) |
|---|---|---|
| 1. 구성표의 이 화면 줄 | 학생이 할 생각 · 주 구성요소 · 판단 자료를 구성표에서 그대로 옮겨 적는다. 안 1·안 2 중 교사가 고른 것. 교과서 문제 화면이면 한 문제인가 | 만든 것과 다른 점. 없으면 「없음」. 있으면 만들기 전에 교사에게 물었는가 |
| 2. 판단 자료 | 발문이 가리키는 그래프·그림·표와 들어갈 구성요소. 없으면 「없음」 | 화면에 실제로 있는가 |
| 3. 발문마다 답할 수단 | 발문 목록과 각 발문의 답 수단(답 칸, 끌 수 있는 점이 있는 그래프, 그림판, 카드 정렬 등) | 발문 수와 답 수단이 맞는가 |
| 4. 반응(피드백) | 조작·입력마다 학생이 보는 반응과 고른 이유(`design-rules.md` 0절 피드백 고르기). 교사가 검토하는 화면은 「해당 없음(교사 검토)」 | 미리보기에서 정답·오답을 넣어 반응을 봤는가 |
| 5. 제작법 | 쓰는 구성요소의 제작법이 reference에 있는가. 없으면 복사본 시험 계획 | 「계획 대비 후퇴」가 있으면 보고했는가 |
| 6. 글씨와 색 (권고) | h2로 쓸 문장(핵심·선언·지시), 쓸 역할 색과 칠할 말(화면마다 1~2곳). 쓰지 않으면 「쓰지 않음」과 이유만 적는다 | 저장값에 h2와 색 글자가 들어갔는가 |
| 7. 정답 노출·수식 | 시작 상태에서 보이면 안 되는 값, 모든 수식·숫자는 수식 노드 | 2-0절 시작 상태 표, 1절 점검 결과 |
| 8. 배치 | 열 구성, 지시 위치, 표의 열 수(이름 열 포함, 두 열 화면 5열 이상·한 열 화면 7열 이상이면 행열을 뒤바꾼 모양으로 계획), 표 머리글에 쓸 말(`design-rules.md` 2절 「표로 답을 받을 때」), 풀이 공간이 필요한 화면이면 리걸패드(두 열 1:1, 전체 폭 16:9). 교과서 문제 화면은 풀이 공간을 기본으로 둔다(교사가 뺐으면 구성표 기록 확인) | 측정한 창 크기와 스크롤 결과(2-1절) |
| 9. 구성요소 조합·계획 대조 | 쓸 구성요소를 키 이름으로 전부 나열(메모 제외 개수 포함)하고, 조합 제약을 확인한다(전체 화면 구성요소(카드 정렬 등)는 빈 화면에 하나만, 그래프 종류, 그리기 발문이면 그릴 수단). 제작법이 없으면 5번과 같이 복사본 시험 계획 | 2-3절 대조 결과(빠진 것 0건). 1건이라도 있으면 이 화면은 「미완성: 빠진 것」 |

- 색 프리셋, 사용자 지침(문체·용어·색 지정), 교사가 준 이미지의 크기·선명도·경로(`illustration.md`)는 활동을 시작할 때 한 번 적고, 바뀔 때만 다시 적는다.
- 여러 화면을 한꺼번에 고칠 때도 화면마다 표를 채운다.

## 4. 종료 보고 (관문 G4)
작업을 마칠 때 교사에게는 평문으로 짧게 말한다: 완료한 화면, 미완성인 화면(빠진 것), 해 보지 못한 것, 계획과 달라진 것(「계획 대비 후퇴」 포함). 못 지킨 것을 숨기지 않는다.
- **「완료」와 「미완성: 빠진 것」을 나눠 말한다.** 필수 실패가 1건 이상이거나 계획 대조에서 빠진 것이 있는 화면은 「완료」에 넣지 않는다. 「초안」·「배치만 했다」는 완료가 아니다. 「자동 점검 0건」을 완성의 근거로 쓰지 않는다.
- 「계획 대비 후퇴」는 구성표에서 정한 구성요소를 만들지 못해 바꾼 것이다.
- 말하기 전에 **활동 전체를 한 번 훑는다**(교사 화면에 쓰지 않는다): ① 같은 종류 칸의 피드백 표시가 같은가 ② 학생에게 반응이 없는 조작 화면 ③ 답 수단이 없는 발문 ④ 판단 자료가 없는 화면 ⑤ 같은 학생 행동 흐름이 되풀이되는 화면과 그 이유(`brainstorming.md` 0-4). 찾은 것 중 고치지 못한 것만 교사에게 말한다.

**점검 내역을 보여 달라는 요청이 있을 때만** 아래를 붙인다.
1. 규칙 표:

| 지킨 규칙 | 못 지킨 규칙(이유) | 확인하지 못한 것 | 계획 대비 후퇴 |
|---|---|---|---|
| (예: 시작 선언, 수식 노드, 점검 0건) | (예: 대체 텍스트 비어 있음 — 이미지 업로드 실패) | (예: 학생 계정에서의 동작) | (예: Polypad(폴리패드) 대수 타일 계획 → 그래프 넓이 모형으로 바꿈, 제작법 미확인, 교사 확인 받음) |

2. 최종 구성요소 분포표(`brainstorming.md` 0-4). 확정 때와 달라졌으면 어디가 왜 달라졌는지 적는다.
3. 화면별 완성도 표: 화면 · 평가(상 / 중 / 하) · 근거 한 줄 · 측정한 창 크기와 스크롤.
