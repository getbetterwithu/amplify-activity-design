# Amplify 액티비티 설계 스킬 (activity-design)

액티비티를 **자동으로 만들어 주는 스킬이 아니다.** 설계 규칙과 편집기 조작 절차를 알려 주고, 사용자의 지시 범위 안에서 AI가 함께 만들도록 돕는다. 모든 지식은 실제 제작에서 편집기와 저장값으로 확인한 것이며, 확인 정도를 항목 끝에 적었다. Amplify는 편집기 내부 구조를 바꿀 수 있으므로 조작 절차는 확인 날짜를 보고 판단한다.

## 절대 원칙: 사용자가 바꾼 것을 되돌리지 않는다
사용자가 편집기에서 직접 바꾼 것은 그 자체가 가장 우선하는 설계 결정이다. 함부로 되돌리지 않는다. 다른 모든 규칙보다 앞선다.
- 화면을 고치거나 다시 만들기 전에 **반드시 지금 저장값을 다시 읽고**, 내가 마지막으로 저장한 값과 비교해 사용자가 바꾼 곳을 찾는다. 내가 갖고 있던 예전 화면 JSON으로 화면을 통째로 다시 만들면 사용자가 고친 것이 지워진다(2026-11-09 실제 사고: 사용자가 옮긴 문제 위치와 켜 둔 테두리를 되돌림).
- 바뀐 것을 찾으면 **그대로 두고, 무엇을 어떻게 바꿨는지 보고한 뒤 의도를 묻는다.** 이 스킬의 다른 규칙과 달라 보여도 사용자 변경이 이긴다.
- 확인한 의도에 맞춰 **나머지 화면의 방향을 정한다.** 사용자가 고친 화면은 다른 화면을 어떻게 만들어야 하는지 보여 주는 본보기다.

## 가장 중요한 철학: 글자는 최대한 적게
글자가 적어야 학생이 생각할 여지가 많다. 학생이 답으로 이미 확인한 내용을 화면이 다시 정리해 보여 주지 않고, 정리가 필요하면 학생이 직접 서술하게 한다. 같은 말을 두 번 쓰지 않는다(예: 메모에 발문이 있으면 객관식 `prompt`는 `""`). 다른 모든 규칙보다 앞선다. 자세한 기준은 `reference/design-rules.md` 0절.

## 사용자 지침이 우선한다
사용자의 개인·프로젝트 지침(용어, 문체, 색 지정, 교사 참고 사항 형식, 진행 약속)이 있으면 그것이 이 스킬의 기본값보다 우선한다. 이 스킬에는 누구에게나 통하는 원칙과 조작법만 둔다.

## 처음 쓸 때 물어볼 것 (사용자 지침에 답이 없을 때만)
- **색 프리셋 (스킬을 처음 호출했을 때 가장 먼저)**: 작업을 시작하기 전에 `reference/color-presets-swatch.html`을 답변의 `visual` 블록으로 그대로 보여 준다(① 기본형 / ② 차분형 / ③ 색약 배려형의 실제 색 견본, 흰 바탕 메모 글자, 수직선 예). 그리고 「어떤 것을 기본 색상으로 쓸까요?」라고 묻고, 답을 받은 뒤에 시작한다. 색 이름이나 hex만 나열해 묻지 않는다. 고른 프리셋을 그 활동의 기본 색 규칙으로 기록한다. 이미 기록된 활동을 이어서 할 때는 다시 묻지 않는다. (사용자 지시, 2026-11-10)
- **축하 팝업**: 정답이 있는 첫 화면에서 한 번 보여 주고 묻는다(`design-rules.md` 5-1).

## 일하는 순서
1. 사용자와 **화면 설계**(무엇을 발견·이해하게 할 화면인가)를 먼저 정한다. 편집기를 건드리기 전에 `design-rules.md`의 구성요소 배치를 보고 조합을 제안한다.
2. 이미지가 필요하면 만들고 확인한 뒤 `editor-ops.md` 절차로 넣는다.
3. 편집기에 쓰는 일(입력·삭제·이동·저장)은 **사용자가 명시적으로 지시한 뒤에만** 한다. 읽기(저장값 조회)는 활동을 바꾸지 않는다.
4. 바꿀 때마다 **저장값으로 확인**한다. 화면에 그렇게 보이는 것만으로 끝내지 않는다.
5. 사용자가 켜 둔 설정이 이상해 보여도 먼저 묻고, 임의로 되돌리지 않는다. 사용자가 고친 글·설정·배치·구성요소·CL은 저장값을 먼저 읽고 그대로 둔다(절대 원칙). 화면을 다시 만들 때는 지금 저장값을 바탕으로 필요한 부분만 바꾼다.
6. **새 방법은 화면 복사본에서 시험하고 안전하게 지운다**(`editor-ops.md` 2절). 원본 화면에서 시험하지 않는다.
7. **작업을 마친 뒤 스킬 업데이트를 제안한다.** 이번 작업에서 사용자가 고치거나 지적한 것, 새로 확인한 조작법을 모두 목록으로 보여 준다. 각 항목을 AI가 먼저 두 가지로 나눠 판단을 보여 준다.
   - **공통(사실·원칙):** Amplify 동작, 수학 표기, 누구에게나 도움이 되는 설계 원칙. 이 스킬에 넣는다.
   - **개인 취향:** 이 사용자에게만 맞는 값·운영 방식. 사용자의 개인·프로젝트 지침에 넣는다.
   - 분류가 애매한 항목은 따로 표시하고 왜 애매한지 한 줄로 덧붙인다.
   - 끝에 「이대로 스킬을 업데이트할까요?」라고 묻고, 사용자가 번호별로 고친 분류를 반영한 뒤에 고친다. 승인 없이 스킬 파일을 고치지 않는다.

## 이 스킬이 하지 않는 것
- 발행·공유 설정을 바꾸지 않는다(사용자가 지시했을 때만).
- 공식 Amplify 액티비티의 CL 원문이나 그래프 상태를 옮겨 적거나 배포하지 않는다.
- 특정 교사의 용어·문체·색 규칙을 정하지 않는다. 그런 규칙은 사용자의 프로젝트 지침을 따른다.
