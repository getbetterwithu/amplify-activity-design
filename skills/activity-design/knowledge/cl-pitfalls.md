# CL·구성요소 함정

> 액티비티를 만들며 확인한 함정과, 자료끼리 어긋날 때 따를 판정이다. 확인된 동작 전체는 `cl-judgments.md`에 있다.
> **`cl-judgments.md`와 이 문서에 없는 sink·source·함수는 쓰지 않는다.** `cl-sinks.md` 목록에 이름이 있어도 쓰임이 적혀 있지 않으면 쓰지 않는다. 필요하면 쓰기 전에 교사에게 묻는다.

## 1. 만들며 확인한 함정

### CL에서 사칙연산은 문자열 수식으로 계산한다 (확인됨)
- `+`, `-`, `*`, `/`를 CL 식에 직접 쓰지 않는다. 예: `btn.pressCount + 1`, `makeBounds(-0.05*m, …)`는 계산되지 않는다.
- 계산식 전체를 큰따옴표 안에 글자로 쓰고 `numericValue("…")`로 감싼다. 식에 들어가는 구성요소 값·변수는 `${…}`로 감싸 넣어야 숫자로 바뀌어 계산된다. 숫자 자체(`1`, `0.05`)는 그대로 쓴다.
  - 덧셈: `cal = numericValue("${a.numericValue}+${b.numericValue}")`
  - 뺄셈·나눗셈: `numericValue("${a.numericValue}-${b.numericValue}")`, `numericValue("${a.numericValue}/${b.numericValue}")`
  - 곱셈·상수: `numericValue("-0.05*${m}")`, `numericValue("${btn.pressCount}+1")`
- 숫자 앞의 마이너스(`-0.08`)는 그대로 된다.
- 예: 두 칸 값의 계산 결과와 학생 답을 비교해 메모에 피드백을 띄운다.
  ```
  cal = numericValue("${a.numericValue}+${b.numericValue}")
  answer = input.numericValue
  show = when cal = answer "참 잘했어요" otherwise "다시 계산해 보세요"
  ```
  이 꼴은 제출 전 입력하는 동안에도 판정한다. 제출 뒤에만 보이게 하려면 `input.submitted` 조건을 함께 건다.

### 정렬 리스트: `matchesKey`로 순서를 판정한다 (확인됨)
- 편집기에서 항목을 **정답 순서대로** 입력하면 그 순서가 정답이 되고, 학생 화면에서는 섞여 나온다.
- 다른 구성요소의 CL에서 `별칭.matchesKey`를 읽는다. 예: 메모 CL `say = when order.matchesKey "성공" otherwise "실패"`, 메모 내용에 `${say}`.
- 정렬 리스트에는 ✅/❌를 붙이는 sink(`suffix` 류)가 없다. 피드백은 메모, 화면 부제(`subtitle`), 다음 단계 열기(`hidden: not(order.matchesKey)`)로 준다.

### 전체 화면 구성요소(카드 정렬 등)는 빈 화면에 하나만 둔다 (확인됨)
- 그래핑 계산기, 구슬 굴리기, 카드 정렬, Class Gallery(교실 갤러리), Polygraph(폴리그래프)는 구성요소 목록의 「전체 화면」 아래에 있는 전체 화면 구성요소다. 화면에 다른 구성요소가 하나라도 있으면 추가 버튼이 비활성화된다. 그래서 이 구성요소를 쓰는 화면에는 메모·답칸을 함께 둘 수 없다. 학생 지시는 화면 부제에, 설명은 교사 팁에 둔다.
- 카드 정렬에는 CL sink가 없다. 판정은 화면 CL에서 `별칭.matchesKey`를 읽어 부제에 띄운다.

### 객관식: 편집기에서 정답 표시를 해야 `matchesKey`·`correct`가 의미를 가진다 (확인됨)
- 정답 표시가 없으면 `matchesKey`는 늘 거짓이다. 정렬 리스트는 입력한 순서가 곧 정답이라 따로 표시하지 않는다.

### 수식 답변: CL에 `prompt`를 쓰지 않는다 (확인됨)
- 수식 답변에는 `prompt` sink가 없어 편집기에 오류가 뜬다. 질문과 피드백은 앞에 메모로 둔다.

### `timeSincePress()`는 괄호를 꼭 쓴다 (확인됨)
- `btn.timeSincePress`처럼 괄호 없이 쓰면 작동하지 않는다. `timeSinceSubmit`도 확인된 예(`timeSinceSubmit()`, `timeSinceSubmit(20)`)는 모두 괄호를 쓴 꼴이므로 같이 쓴다.

### 자동화로 흉내 낸 끌기는 판정 근거로 쓰지 않는다 (확인됨)
- 학생 미리보기에서 스크립트로 끌기를 흉내 내면 화면 모양만 바뀌고 구성요소 상태(순서, 위치)는 그대로일 수 있다. 그 결과로 「동작하지 않는다」고 판정하지 않는다.
- 판정이 필요하면 사람이 직접 조작하거나, 저장값·CL 값이 바뀌었는지 함께 확인한다.

### 폴리패드가 있는 화면: 수식 답변의 `correct`가 오류 경고를 냈다 (확인됨)
- 일부 화면 폴리패드와 수식 답변을 한 화면에 두고 수식 답변에 `correct: ok`를 넣으면, 학생 미리보기 머리에 「연산 레이어 오류 때문에 화면이 대시보드와 일치하지 않을 수 있습니다」가 떴다. `correct`만 빼면 경고가 사라지고, `suffix`로 붙인 ✅/❌는 그대로 동작했다.
- 이런 화면에서는 `suffix`로 ✅/❌만 보여 준다. `correct`를 넣었다면 미리보기 머리에 경고가 뜨는지 꼭 본다. `correct`를 빼면 대시보드 요약 칸에는 판정 없는 응답(●)으로 보이므로, 이 점을 교사에게 알린다.
- 경고의 원인이 폴리패드인지 판정 식인지는 모른다. (미확인)

## 2. 자료끼리 어긋날 때의 판정

- **`differenceFunction`의 부호**: 공식 문서의 설명은 좌변 − 우변, 예시 주석은 우변 − 좌변으로 서로 반대다. 판정은 **좌변 − 우변**이다(`cl-judgments.md` 11절).
- **`readOnly`**: 「화면이 보기 전용으로 바뀐다」는 설명이 있으나, 실제로는 학생의 입력·선택·제출·조작을 막지 않고 대시보드 정오답 채점에서만 빠진다(`cl-judgments.md` 10절).
